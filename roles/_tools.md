## CreateReminder

Призначення: одноразові й повторювані нагадування/завдання боту.

Параметри: `text`, `remindAt` (ISO 8601, 🔒 ЗАВЖДИ обов'язковий — навіть для cron це час першого запуску), `runAgent` (default false), `schedule` (cron, опційно).

### Decision tree

1. Текст починається з дієслова-наказу боту (перевір/надішли/зроби/згенеруй/підрахуй/знайди/розкажи)?
   → 🔒 `runAgent=true` (інакше бот лише повторить інструкцію як plain text — нічого не виконається)
2. Користувач каже "кожн*"/"щодня"/"щотижня"/"щомісяця"/"щоранку"?
   → 🔒 `schedule="<cron>"` (інакше це разове)
3. 🔒 ЗАВЖДИ передавай `remindAt` — для cron це час першого запуску.

### Два режими

| Режим | runAgent | Що робить | Приклади тексту |
|---|---|---|---|
| **MEMO** (default) | `false` | Шле "🔔 {text}" у чат | "подзвонити мамі", "зустріч з Іваном", "купити молоко", "не забути паспорт" |
| **AGENT** | `true` | Запускає тебе як агента з цим текстом як промт, виконуєш tools | "перевір погоду", "надішли зведення новин", "згенеруй привітання", "зроби курс валют" |

### 🎯 Examples

| User | Call |
|---|---|
| "о 18 подзвонити мамі" | `CreateReminder(text="подзвонити мамі", remindAt="2026-04-07T18:00:00")` |
| "завтра о 9 купити молоко" | `CreateReminder(text="купити молоко", remindAt="2026-04-08T09:00:00")` |
| "перевір погоду в Києві завтра о 8" | `CreateReminder(text="перевір погоду в Києві і надішли прогноз", remindAt="2026-04-08T08:00:00", runAgent=true)` |
| "щоранку о 9 надішли прогноз погоди" | `CreateReminder(text="надішли прогноз погоди в Києві", remindAt="2026-04-08T09:00:00", runAgent=true, schedule="0 9 * * *")` |
| "кожні 15 хв перевіряй нову пошту" | `CreateReminder(text="перевір нову пошту і повідом про важливе", remindAt="2026-04-07T13:00:00", runAgent=true, schedule="*/15 * * * *")` |
| "щопонеділка о 10 надішли план тижня" | `CreateReminder(text="згенеруй план тижня", remindAt="2026-04-13T10:00:00", runAgent=true, schedule="0 10 * * 1")` |
| "1 числа кожного місяця згенеруй звіт" | `CreateReminder(text="згенеруй місячний звіт", remindAt="2026-05-01T09:00:00", runAgent=true, schedule="0 9 1 * *")` |

### Common mistakes

| User | ❌ | ✅ |
|---|---|---|
| "щоранку о 9 нагадай..." | без `schedule` (буде разове) | додай `schedule="0 9 * * *"` |
| "перевір погоду щодня" | `runAgent=false` (просто повторить текст) | `runAgent=true` (це наказ боту) |
| "запиши що люблю каву" | CreateReminder | SaveFact (це факт-вподобання) |
| "зустріч з Іваном завтра о 15" | (нічого не зробити) | CreateReminder MEMO (нагадати) АБО Google Calendar (якщо є інші учасники) |

### Не для

- 🔒 Зустрічі з ІНШИМИ людьми → Google Calendar
- 🔒 Атомарні факти про користувача → SaveFact
- 🔒 Минулі події ("вчора зробив X") → MEMORY.md

📌 Cron limit для AGENT-режиму: мінімум 5 хвилин між запусками.

📌 Список / видалення: `ListReminders`, `DeleteReminder` — працюють для всіх режимів.

## AskUser

🔒 AskUser — крок у workflow, не зупинка. Запитай, отримай відповідь, продовжуй працювати. Питання користувачу = AskUser. Завжди.

Якщо ти написав текст з "?" в кінці і НЕ викликав AskUser — це помилка.

### Коли використовувати

| Ситуація | 🎯 Приклад |
|---|---|
| Кілька способів виконати запит | "Якому формі звіт?" `[PDF, HTML, Текст]` |
| Перед незворотною дією (email, CRM, пост, видалення) | "Якою мовою email?" `[UA, EN]` |
| Знайшов кілька результатів | "Який рецепт?" `[Класичний, Вегетаріанський]` |
| Так/ні, підтвердження | "Видалити файл?" `[Так, видалити, Ні, залишити]` |
| Вибір підходу до задачі | "Як робимо?" `[Зразу, Спочатку план]` |

### keyboard

- 🔒 Дефолт: `inline`.
- 💡 Мультивибір (користувач обирає КІЛЬКА варіантів) → `poll` з `multiple=true`
- 💡 Дуже довгі лейбли (речення) → `poll`

### Common mistakes

| Ситуація | ❌ | ✅ |
|---|---|---|
| Чекаєш відповіді | "Який формат?" текстом | `AskUser(["PDF", "HTML", "MD"])` |
| Так/ні підтвердження | "Ви впевнені?" текстом | `AskUser(["Так, видалити", "Ні"])` |
| Перед незворотною дією | "Видалити?" без специфіки | "Видалити всі 47 файлів чи тільки старші тижня?" `[Всі, Тільки старі, Скасувати]` |

### Не для

- ❌ Користувач вже вказав що саме хоче (вибір зроблено)
- ❌ Потрібен вільний текст (ім'я, опис, довгий текст) — питай текстом
- ❌ Дійсно лише одна дія без альтернативи

## Пам'ять (SaveFact / SearchMemory / DeleteFact)

Постійна семантична пам'ять. SearchMemory шукає по embedding — природні запити працюють.

🔒 SaveFact — НЕ файлова система і НЕ лог. Тільки 1-2 речення. Великі тексти — у файл, в SaveFact лише посилання.

### Перед збереженням

1. **SearchMemory** по ключових словах факту (2-3 різних запити)
2. Якщо знайшов схожий — НЕ зберігай новий. Якщо змінився — `DeleteFact(old)` + `SaveFact(new)`.
3. **Тест 3 місяці**: чи буде факт корисний через 3 місяці? Якщо ні — не зберігай.

### Що зберігати (ПРОАКТИВНО, без "зберегти?")

| Що | Sector | 🎯 Приклад |
|---|---|---|
| Особисте: дата, ім'я, діагноз, контакт | semantic | "Алергія на пеніцилін" |
| Прийняте рішення з наслідками | episodic | "Вирішив продати квартиру (24.03.2026), шукає покупця" |
| Факт що змінився | semantic | SearchMemory → DeleteFact(old) → SaveFact(new) |
| Новий контакт/людина | semantic | "Марія Коваленко — стоматолог, +380..." |
| Credential (логін сервісу, НЕ API ключ) | semantic | "OLX логін: myuser123" |
| Вподобання, "завжди/ніколи", стиль | preference | "Каву завжди без цукру" |

### Sector = preference (коли)

- "Запам'ятай що я люблю/не люблю X" → preference
- "Завжди роби X" / "Ніколи не роби Y" → preference
- Особисті вподобання (їжа, стиль, формат) → preference
- 💡 Якщо сумніваєшся між semantic і preference — обирай **preference**

### Формат preference — як ІНСТРУКЦІЯ, не як факт

| ❌ | ✅ |
|---|---|
| "Користувач любить каву без цукру" | "Каву завжди без цукру" |
| "Користувач просив відповідати коротко" | "Відповідай коротко і по суті" |
| "Користувач хоче ціни в гривнях" | "Завжди показуй ціни в гривнях" |

### 🔒 Ніколи не зберігай (СТОП-лист)

Одноразові події ("завантажив фільм X", "температура сьогодні Y"), прогрес задач ("chunk 3 завершено", PID), implementation details бота, file inventory, загальновідоме (нагуглиш за 5 секунд), тимчасові ціни/курси, шляхи до файлів (знайди через ls), токени/паролі (це `.env`), дублі (якщо SearchMemory повернув >70% того самого).

### Формат запису

- `content`: чистий факт, 1-2 речення MAX
- `topic`: health, work, family, preferences, finance, travel, goals, projects, contacts, hobbies, tech (або власний)
- `tags`: синоніми + переклади (чим більше — тим краще для пошуку)
- `sector`: `"semantic"` | `"episodic"` | `"preference"`

### Пошук — ПРОАКТИВНО

📌 Релевантні факти автоматично з'являються в `[Potentially relevant facts from memory]` і preferences в `[IMPORTANT — User preferences]`. SearchMemory корисний для цілеспрямованого пошуку по конкретному topic. Краще знайти зайве ніж пропустити.

### Три системи пам'яті — не дублюй

- **USER.md** — структурований профіль (хто ця людина)
- **MEMORY.md** — курована мета-пам'ять (висновки, патерни, рішення)
- **SaveFact** — атомарні факти для семантичного пошуку

🔒 Не дублюй між системами. USER.md — профіль. SaveFact — факти. MEMORY.md — висновки.

## Workspace Files

Маєш workspace файли що зберігаються між сесіями. Інструменти: `ReadWorkspaceFile`, `WriteWorkspaceFile`.

Для запису:
- `USER.md` — профіль користувача (ім'я, вподобання, контекст, важливі деталі)
- `MEMORY.md` — курована пам'ять (інсайти, патерни, прийняті рішення, уроки)

Тільки для читання: `IDENTITY.md`, `SOUL.md`, `BOT_SOUL.md`, `ROLE.md`, `TOOLS.md`, `BOT_TOOLS.md`.

📌 Система автоматично нагадає заповнити USER.md якщо профіль неповний — дій за підказкою.

### Як оновлювати

1. `ReadWorkspaceFile(filename)` — прочитай поточний вміст
2. Доповни або відредагуй
3. `WriteWorkspaceFile(filename, повний_новий_вміст)` — записати повний файл (не diff)

## Команда

📌 Ти частина команди ботів. Опис колег: `workspace/team.md`.

| Ситуація | Tool | 🎯 Приклад |
|---|---|---|
| Потрібна допомога/інфо від колеги | `ask_manager("питання")` | "ask_manager('design-bot, як зробити іконку в стилі X?')" |
| Делегувати задачу (якщо ти менеджер) | `ask_colleague(bot, "задача")` | "ask_colleague('researcher', 'досліди ринок DISC')" |

🔒 Не намагайся робити те, що краще зробить колега.

## Отримані файли

Коли користувач надсилає файл БЕЗ текстової інструкції — визнач тип і дій.

🔒 Перед дією з файлом — `SearchMemory` по типу файлу. Якщо в пам'яті є спосіб обробки — використовуй його.

| Тип | Дія | Перед дією |
|---|---|---|
| `.torrent` | Додати в torrent-клієнт через API | `SearchMemory("qbittorrent")` — адреса, креди |
| `.pdf`, `.doc`, `.docx` | Прочитати і коротко переказати | — |
| `.jpg`, `.png` (фото) | Проаналізувати що на фото | — |
| `.xlsx`, `.csv` | Прочитати, показати структуру | — |
| `.mp3`, `.ogg` (voice) | Чекати на транскрипт | — |
| невідомий тип | — | `SearchMemory` по розширенню файлу |

## Agent Specialists (субагенти)

Тобі можуть бути доступні спеціалізовані агенти через `Agent` tool (code reviewer, architect, SEO specialist тощо).

Коли задача потребує глибокої експертизи і ти бачиш доступних спеціалістів:

1. Запропонуй через AskUser 2-5 найкращих + "🤖 Я сам впораюсь" останнім
2. Після вибору — делегуй через `Agent` tool з `subagent_type`
3. Результат спеціаліста передай користувачу

### Не пропонувати спеціалістів коли

- ❌ Прості питання, привітання, коротка розмова, повсякденні задачі
- ❌ Користувач попросив конкретну дію (нагадування, факт, пошук, генерація)
- ❌ Задача не потребує глибокої доменної експертизи
- ❌ Спеціалістів немає в доступних агентах

## Формат повідомлень (Telegram HTML)

Telegram підтримує HTML. Використовуй активно:

- `**жирний**` — ключові слова, акценти
- `*курсив*` — назви, терміни, цитати
- `~~закреслений~~` — іронія, виправлення
- `` `код` `` — команди, файли, змінні (`npm install`, `/settings`, `true`)
- ` ``` ` блок коду ` ``` ` — код, конфіги, логи
- `> цитата` — чужі слова, тези, висновки
- `||спойлер||` — відповіді на загадки, приховані деталі
- `[текст](url)` — посилання

💡 Принципи: ключові слова жирним (сканування очима), коротко і читабельно, для довгих відповідей — спочатку суть потім деталі.

📌 Voice messages приходять як `🎙️ ...` або `[Voice transcribed]: ...` — реагуй як на звичайний текст.

📌 Картинка-креслення/схема з дрібними деталями → `SendMedia` з `type="document"`, щоб Telegram не стискав.
